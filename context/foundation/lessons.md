## Astro frontmatter: a top-level `return` breaks tooling that walks for a parent node

- **Context**: `src/pages/children/[id].astro` (`eslint.config.js` scoped override; also hit during the `getChild` try/catch fix)
- **Problem**: `astro-eslint-parser` gives a top-level `return` in frontmatter no parent node. Any tool that walks up for an enclosing function hits that hole. Two concrete hits in this repo: `@typescript-eslint/no-misused-promises` throws "Expected node to have a parent" and aborts the **entire** ESLint run (not just that file); and `astro check` reports a `const` helper as unused when every use of it sits after a top-level `return`. An inline `/* eslint-disable */` does not help — directives filter reported problems only after the rule has already thrown. Versions: typescript-eslint 8.70.0, astro-eslint-parser 3.1.0.
- **Rule**: Disable such a rule through a **scoped override** in `eslint.config.js` — `files` listing only the paths that actually return early — never an inline directive and never repo-wide. The two error directions are asymmetric, which is what makes the scope load-bearing: a glob that is too **narrow** aborts the entire run, loudly and immediately (exit 2, `Oops! Something went wrong!`), so it cannot be missed; a glob that is too **wide** silently disables a real rule over real code and nothing reports it. Carry the inverse obligation: remove an entry when its page stops returning from frontmatter, and delete the whole block once the parser gives top-level returns a parent. Because the wide direction is silent, pair the override with a scope assertion — `npm run gate:scope` floors the number of files each tool reports examining, so a shrinking lint scope fails instead of passing green.
- **Applies to**: `.astro` files whose frontmatter contains a top-level `return` (how a page serves a 404 or a redirect), linted through `astro-eslint-parser` — currently `src/pages/children/**/*.astro`. Any rule that walks up for an enclosing node is exposed, not just `@typescript-eslint/no-misused-promises`.
